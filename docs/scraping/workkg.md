# Work.kg parser report

## Краткий вывод
`work.kg` — это **SSR job board на WordPress** с плагином **WP Job Manager** и темой **Flatsome**. Сайт хорошо парсится без тяжёлого JavaScript: **листинги и детальные страницы уже содержат почти все нужные данные в HTML и JSON-LD**, а динамика в основном ограничена подгрузкой дополнительных вакансий через AJAX и трекингом аналитики.

Для нашего сценария это удобный источник, потому что у сайта есть:
- понятные URL для отраслевых разделов, включая `IT`
- стабильные карточки вакансий в выдаче
- отдельная детальная страница с `JobPosting` JSON-LD
- простая схема отклика через `mailto:` вместо сложного auth/apply-flow
- AJAX `load more`, который можно использовать как вторичный путь добора вакансий

## Стек и инфраструктура
На странице явно видны сигналы стека:
- **WordPress** как CMS
- **WP Job Manager** для вакансий
- **Flatsome** как тема
- **Yandex Metrika** и **Google Analytics** как аналитика
- **AdSense / Google Ads** как рекламные интеграции

Это важно для парсера, потому что большую часть данных лучше брать из HTML и JSON-LD, а AJAX использовать только как fallback для подгрузки списка.

## Типы страниц
### Home
Главная страница `https://work.kg/` содержит общий поиск по вакансиям, список последних вакансий, список отраслей и текстовый блок о трудоустройстве.

### Listing / search
Отраслевые страницы вроде `https://work.kg/it/` показывают уже отфильтрованный список. Для IT-раздела сайт прямо сообщает, что поиск выполнен и найдено `34` совпадения.

### Detail
Детальная страница вакансии показывает:
- название
- локацию
- дату публикации
- компанию
- описание
- условия отклика
- кнопку `Откликнуться`

### Company / apply
Отдельной публичной страницы компании в показанных шаблонах я не нашёл. Компания отображается прямо внутри вакансии. Отклик устроен через **email**: кнопка `Откликнуться` раскрывает текст и `mailto:`-ссылку.

## Home page
Главная страница — это не просто лендинг, а полноценная точка входа в поиск.

### Основные блоки
- логотип и навигация
- ссылки `Мои вакансии` и `Опубликовать вакансию`
- заголовок `Поиск работы в Бишкеке, Кыргызстане`
- поля `Ключевые слова` и `Локация`
- чекбокс `Только дистанционные вакансии`
- выбор категории через dropdown/listbox
- кнопка `Поиск вакансий`
- набор чекбоксов по типам занятости
- выдача свежих вакансий
- блок `Вакансии по отраслям`
- текстовый информационный блок и footer

### Поля поиска
На главной видно следующие контролы:
- `textbox` для ключевых слов
- `textbox` для локации
- `checkbox` для удалённой работы
- `combobox/listbox` для категории
- чекбоксы занятости: `Временная работа`, `Полная занятость`, `Практика`, `Фриланс`, `Частичная занятость`

Важно: **на странице нет обычного `<form>`**, то есть поиск собран как UI-контролы, а не как классическая HTML-форма. Для парсера это значит, что нельзя полагаться на submit формы как на основной механизм навигации.

### Карточка вакансии на home
Карточка в выдаче рендерится как ссылка на детальную страницу. Внутри неё обычно есть:
- логотип компании
- `h3` с названием должности
- `strong` с названием компании
- локация
- метка `(Удаленно)` если есть
- тип занятости
- `time` с датой публикации

### URL-паттерн карточек
Карточки ведут на URL вида:
- `https://work.kg/job/<slug>/`

Это очень хороший стабильный якорь. Для парсинга списка достаточно собирать все ссылки, начинающиеся с `https://work.kg/job/`.

## Структура карточки вакансии
Карточка в листинге устроена очень просто и семантично.

### Типовые элементы карточки
- `a[href^="https://work.kg/job/"]` как корневая ссылка карточки
- `img` с логотипом компании
- `h3` с названием вакансии
- `strong` с названием компании
- текстовый блок локации
- `time` с временем публикации
- дополнительные текстовые метки, например `(Удаленно)`
- список типов занятости

### Что важно для extraction
Лучше всего извлекать поля так:
- `title` из `h3`
- `company` из `strong`
- `location` из текстового блока рядом с гео
- `remote` по тексту `(Удаленно)` или по чекбоксам/фильтрам категории
- `employment type` из списка в карточке
- `published_at` из `time`

### Особенность карточек
На home и в категории карточки могут содержать разный набор полей, но **базовая структура остается одинаковой**. Это значит, что один extractor может покрывать оба сценария без отдельной логики для home и `IT`.

## Detail page

### Верхний блок
- `h1` с названием вакансии
- ссылка на локацию в Google Maps
- `time` с датой публикации
- логотип компании

### Описание вакансии
Тело вакансии структурировано как последовательность абзацев с жирными заголовками:
- `Обязанности:`

Это удобно для скрапа, потому что даже без JSON-LD можно собрать смысловые секции прямым текстовым парсингом.

### Apply flow
Кнопка `Откликнуться` не ведёт к сложной форме. После клика появляется текст:
- `Для ответа на эту вакансию отправьте подробности по электронной почте`
- `mailto:` ссылка на контактный email

То есть реальный apply-flow здесь — это **email-based apply**, а не встроенная форма.

### Контактные данные
На детальной странице видно:
- email работодателя через `mailto:`
- subject в ссылке, который уже подставлен системой

Это хороший fallback для извлечения `apply_url` и `apply_contact`.

### Навигация по соседним вакансиям
Внизу есть навигация на предыдущую вакансию. Это может помочь строить crawl-цепочку, если нужно идти по похожим объявлениям.

## JSON-LD и embedded state
Это одна из сильных сторон сайта.

### Найденные structured data типы
На детальной странице присутствуют:
- `WebPage`
- `BreadcrumbList`
- `WebSite`
- `Organization`
- `JobPosting`

### Поля `JobPosting`
Из JSON-LD можно достать:
- `datePosted`
- `title`
- `description`
- `hiringOrganization.name`
- `identifier.value`
- `jobLocation.address`
- `directApply`
- `mainEntityOfPage`

### Почему это важно
Для парсера `JobPosting` здесь должен быть **primary source**. DOM нужен как fallback и для проверки контекста, но основную структуру вакансии лучше брать из JSON-LD.

### Дополнительные встроенные объекты
На странице присутствуют полезные JS-конфиги:
- `job_manager_stats` с `ajaxUrl`, `ajaxNonce`, `postId` и статистикой
- `flatsomeVars` с общими настройками темы и `ajaxurl`

Это хороший сигнал, что AJAX у сайта опирается на штатные WordPress/WP Job Manager механизмы.

## Pagination / load more
На `work.kg` нет классической пагинации в виде `?page=2` в показанном сценарии.

### Механика
Есть ссылка-кнопка:
- `Загрузить ещё список вакансий`

Она ведёт на `#`, но при клике реально подгружает дополнительные карточки через AJAX и дописывает их в список.

### Что это значит
Для парсера нужно поддерживать два пути:
- стартовая загрузка страницы
- повторный вызов AJAX-эндпоинта для добора карточек

Это важный момент: **load more** здесь не просто UI-элемент, а настоящий механизм расширения выдачи.

## Primary selectors
Ниже селекторы, которые выглядят наиболее устойчивыми.

### Home / listing
- `a[href^="https://work.kg/job/"]`
- `main h3`
- `main strong`
- `main time`
- `a[href^="https://work.kg/it/"]`
- `a[href^="https://work.kg/"]`
- `a[href="#"]:has-text("Загрузить ещё список вакансий")`

### Detail
- `main article h1`
- `main article time`
- `main article a[href^="https://maps.google.com/maps?q="]`
- `main article strong`
- `main article .application_button`
- `main article a[href^="mailto:"]`

### Fallback selectors
- `script[type="application/ld+json"]`
- `script:has-text("job_manager_stats")`
- `script:has-text("flatsomeVars")`
- `a[href^="https://work.kg/job/"] time`

## Field mapping table
| Field | Primary source | Fallback source |
|---|---|---|
| `title` | `h1` on detail, `h3` in listing | `JobPosting.title` |
| `company_name` | `strong` in listing/detail | `JobPosting.hiringOrganization.name` |
| `location` | text block in listing, Google Maps link / text on detail | `JobPosting.jobLocation.address` |
| `published_at` | `time` tag | `JobPosting.datePosted` |
| `description` | visible paragraphs on detail | `JobPosting.description` |
| `salary` | visible text in detail | detail text / `JobPosting.description` if salary embedded only there |
| `employment_type` | listing badges / text | detail text |
| `remote_flag` | `(Удаленно)` text | listing text / category page |
| `apply_email` | `mailto:` link after click on `Откликнуться` | footer contact email, if same employer use case |
| `apply_subject` | `mailto:` query string | n/a |
| `job_url` | root `a[href^="https://work.kg/job/"]` | `JobPosting.mainEntityOfPage` |
| `category_url` | отраслевые ссылки `/it/`, `/marketing/`, etc. | n/a |

## 2-pass parser strategy
### Pass 1
- load home or отраслевую страницу
- collect all job URLs from `a[href^="https://work.kg/job/"]`
- detect whether the page is `home` or an отраслевой listing
- if `Загрузить ещё список вакансий` exists, click it or call the AJAX endpoint to get the next batch

### Pass 2
- open each detail page
- extract `JobPosting` JSON-LD first
- use DOM as fallback for title, company, location, description, salary, and apply email
- normalize `mailto:` into `apply_email` + `apply_subject`

### Why this order
На `work.kg` JSON-LD и DOM дополняют друг друга, а не конкурируют. Поэтому безопаснее сначала брать structured data, а потом дотягивать человеческий текст из DOM.

## Practical notes
- Сайт хорошо подходит для локального Кыргызстан/Бишкек парсинга, особенно по IT-разделу.
- Отдельной компании-профиля нет, поэтому лучше строить сущность компании прямо из вакансии.
- Для `remote` важно сохранять не только чекбокс, но и текстовый флаг `(Удаленно)`.
- Архивные вакансии на IT-странице тоже присутствуют, поэтому возраст публикации нужно сохранять как есть, а не фильтровать по умолчанию.
